# Формат файлу розборів

Один файл на варіант: `explanations/<variant_id>.json`.

```json
{
  "variant": 646,
  "items": {
    "1": { "review": "<p>…HTML…</p>", "flag": null },
    "2": { "review": "<p>…</p>", "flag": "Моє розв'язання дає «94», а в даних правильна відповідь «103». Причина: …" }
  }
}
```

`review` — HTML. Дозволені теги: `p`, `strong`, `em`, `ul`, `ol`, `li`, `br`, `table`, `tr`, `td`, `th`, `sub`, `sup`.
`flag` — `null`, або текст, якщо власне розв'язання не збігається з правильною відповіддю з даних, або якщо завдання має дефект (одрук, дві правильні відповіді, картинка нечитабельна).

## Правила тексту

1. Мова — українська. Звертання до читача — «ти» або безособове.
2. Ніколи не посилатися на варіанти літерами (А/Б/В/Г): у застосунку варіанти перемішуються. Завжди цитувати текст варіанта в лапках «…».
3. Структура кожного розбору:
   - `<p><strong>Відповідь: «текст правильного варіанта».</strong></p>`
   - Хід розв'язання. Для логіки — покроково (`<ol>`), з таблицею, якщо вона допомагає. Для читання — з посиланням на номери абзаців і короткими цитатами. Для лексики — значення слова, підказка в контексті (стиль, сполучуваність, сенс речення).
   - `<p><strong>Чому інші варіанти не підходять</strong></p>` + `<ul>`, по одному `<li>` на кожний неправильний варіант, з цитатою варіанта і конкретною причиною.
   - `<p><em>Як розпізнати такий тип завдання:</em> …</p>` — 1–3 речення про патерн і прийом розв'язання, який переноситься на інші завдання цього типу.
4. Пояснювати так, щоб людина без підготовки засвоїла прийом, а не лише запам'ятала відповідь. Без води й повторів.
5. Розв'язати завдання самостійно ДО того, як дивитися на правильну відповідь у даних. Якщо не збігається — перевірити ще раз, потім заповнити `flag`. Правильну відповідь у `review` вказувати ту, що в даних, але у `flag` чесно описати розходження.

## Картина серії (`groups`)

Для серії завдань логічного блоку на одну умову у файлі варіанта є об'єкт `"groups"`, ключ — номер першого завдання серії як рядок:

```json
"groups": { "25": "<p>…HTML…</p>" }
```

Це спільна «картина» серії, яку застосунок показує над розбором кожного завдання серії. Зміст: умови в короткому робочому записі (позиції, порядок, «якщо… то» з обома гілками), таблиця або рядок позицій, якщо допомагає, і виведені наперед факти, що справджуються завжди («Р лише на 1–3», «п'ята завжди Х або У»), плюс 1–2 речення про стратегію для такого типу умов. Ті самі правила тексту, що й для `review`: без посилань на літери варіантів, дозволені теги ті самі. Розбори окремих завдань спираються на картину і не повторюють виведення фактів.
